1.6 プロンプトエンジニアリングとガバナンス

プロンプトをコードに埋め込まない、という話です。管理された版を1か所に置き、実行時に参照させます。書き方の工夫より、扱い方の設計が問われます。

就業規則の運用と同じです。各部署がコピーを持つと、いつのまにか版が食い違い、どれが正しいのか誰にも分からなくなります。正本を1つ置いて全員にそこを参照させ、改訂したら正本を差し替える。参照する側は何も変えません。

どこで間違えるのか

テンプレートをアプリにコピーする。 一見早いのですが、版が散り、誰がいつ変えたか分からなくなり、問題が起きても戻せません。複数チームで同じテンプレートを使う場面では特に効いてきます。

本番から下書きを実行する。 作業中の編集がそのまま利用者に出ます。本番は固まった版を指す参照先だけを見るようにします。

会話履歴やツールを扱えないテンプレート種別を選ぶ。 単発のテキスト生成と、履歴やシステム指示やツール利用を伴う対話とでは、必要なテンプレートの種類が違います。

こう言われたら、これを選ぶ

問題文の手がかり選ぶもの理由
承認済みの版だけ使わせる prompt version の ARN を参照 本文をコピーしない
参照先を固定したまま切替 alias アプリを変えずに済む
会話履歴・system・ツール CHAT テンプレート TEXT では扱えない
候補を同じ条件で比べる variants とテスト変数 比較条件が揃う
改善のたたき台がほしい プロンプト最適化 採否は人が決める
変更履歴と監査を残す CloudTrail と IAM 誰がいつ変えたか
下書きを本番に影響なく試す 準備してから実行 alias は動かさない

覚えておく数字と制限

  • Converse の modelId には prompt version の ARN を渡せる。 実行時の値は promptVariables で渡す。本文を各アプリへ配らずに、承認済みの版を共有できる。
  • CHAT テンプレートは会話履歴、system instructions、tool use、プロンプトキャッシュを扱える。 TEXT テンプレートでは扱えない。Converse に対応したモデルが前提になる。
  • Prompt Flows は DRAFT、version、alias に分かれる。本番は alias 経由で不変の version を指し、リリースのたびにアプリの参照先を書き換えない。
  • DRAFT の編集内容を試すときは、version 化や alias の切り替えの前に準備の操作を挟む。本番 alias が指す version には影響しない。
  • ナレッジベースで独自モデルやカスタムモデルを生成に使う場合、基盤モデル向けの既定プロンプトのままでは動かない。orchestration と generation のプロンプトを明示的に設定する。

紛らわしいものの対比

試験では「テンプレートを各アプリにコピーする」という選択肢が必ず紛れています。監査、ロールバック、A/B 比較のいずれかが要件にあれば、その選択肢は落とせます。
