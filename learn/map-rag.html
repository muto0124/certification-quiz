検索経路 — 文書が答えになるまで

RAG の精度は、文書をどう切り、どう探し、どう絞るかで決まります。この経路のどこに何が居るかを押さえると、問題文のシナリオがどの段の話か見分けられます。

上から下へ、文書が答えに変わるまでの6段です。各段には代表サービスを1つだけ置いています。同じ段を争うサービスは次の図にまとめました。

生成のあとは → 呼び出しと推論基盤 取り込むデータの検査は → 安全と統制の関門

同じ段を争うもの

格納先はベクトル検索の規模とグラフ関係の有無で、検索の手当ては精度が出ない症状で分かれます。どれを選ぶかの基準はタスクページに置きました。

どこを読むか

段候補深掘り
取り込み Bedrock Data Automation / Textract / Transcribe 1.3
格納 OpenSearch Serverless / S3 Vectors / Aurora pgvector / Neptune Analytics / Kendra 1.4
検索の手当て ハイブリッド検索 / リランカー / メタデータフィルター / クエリ分解 1.5

このマップだけでは足りない場面: 検索は当たっているのに応答が遅いときは 呼び出しと推論基盤、検索結果の良し悪しを測りたいときは 観測と評価の配線 を見てください。

番号はこのマップが束ねる3タスクの問題です。図に出るサービスと一対一ではありません。クイズの出題範囲に番号を入力して解いてください。
